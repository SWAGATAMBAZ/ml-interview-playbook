Improving model performance & explainability

A favourite open-ended interview question. Answer it with a structured diagnosis, not a list of tricks: check data and evaluation first, diagnose bias vs variance, then apply targeted fixes — features, model choice, regularisation, ensembles, tuning, thresholds. Then explain the model with SHAP, permutation importance and PDPs.

A diagnosis framework (say this out loud)

  1. Is the evaluation right? Correct metric for the business goal, split that mirrors production (time/group), no leakage, enough validation data, compare with a baseline.
  2. Is the data right? Label quality and definition, feature bugs, train/serve skew, distribution shift, missing important signals.
  3. Bias or variance? Compare train vs validation error and learning curves.
    • High train error (bias) → more expressive model, better features, less regularisation, train longer.
    • Big train–val gap (variance) → more data, regularise, simplify, feature selection, bagging, early stopping, augmentation.
  4. Error analysis: where does it fail? Slice by segment, look at the worst examples, confusion matrix — then fix the biggest bucket.
  5. Tune & ensemble once the above is sound; tune thresholds for the decision.
🧒 In plain English

Before you tune the engine, check the speedometer works (evaluation), the fuel is clean (data), and whether the car is too weak (bias) or swerving all over (variance). Tuning hyperparameters is usually the last 1–3%, while fixing data and features is often 10%+.

Data-side improvements (usually the biggest wins)

  • Get more (or more representative) labelled data; active learning to label the most informative examples
  • Fix label noise; clarify the target definition
  • Domain-driven features: ratios, recency/frequency, aggregates over windows, interactions
  • Better handling of missing values, outliers, rare categories
  • Remove leaky / noisy / redundant features
  • External data (weather, holidays, demographics)
  • Augmentation (images, text), synthetic data with care
  • Rebalance training data or reweight classes

Error analysis

  • Slice metrics by segment (region, device, new vs returning users, time) — find where the model is weak and whether it's fair.
  • Inspect top false positives and false negatives manually: label errors? missing feature? different sub-population?
  • Residual plots vs features (regression), confusion matrix (multiclass).
  • Compare against human-level / Bayes error estimates to know how much headroom is left.

SHAP in one minute

∑ Shapley values
$$\phi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(|F|-|S|-1)!}{|F|!}\Big[f(S\cup\{j\})-f(S)\Big]$$

Each feature's average marginal contribution over all orderings of features. Properties: local accuracy (contributions sum to prediction − baseline), consistency, missingness. TreeSHAP computes exact values for tree ensembles in polynomial time; KernelSHAP approximates for any model. Plots: summary/beeswarm (global), waterfall/force (one prediction), dependence plots (interactions).

⚠️ Explanations ≠ causation

All of these describe the model, not the world. A feature with high SHAP may be a proxy. For “what happens if we change X?” you need experiments or causal inference.

Production trade-offs

A 0.3% AUC gain may not justify 10× latency, a 5-model stack, or losing explainability in a regulated domain. Always weigh accuracy against latency, cost, maintainability, robustness, fairness and interpretability, and validate the gain with an online A/B test.

Interview questions

Your model's performance is poor. How do you improve it?

First validate the evaluation (right metric, production-like split, no leakage, baseline comparison). Then diagnose: high bias (train error high) → richer features/model, less regularisation; high variance (train ≪ validation error) → more data, regularisation, simpler model, bagging, early stopping. Do error analysis by slice and inspect worst cases; fix data/label issues; engineer domain features; tune hyperparameters; try ensembles; tune the threshold for the business metric. Validate gains online.

What is stacking and how do you avoid leakage in it?

Stacking trains a meta-model on the predictions of several base models. To avoid leakage the meta-model must be trained on out-of-fold predictions (each base model predicts on folds it wasn't trained on); at inference, base models trained on all data feed the meta-model. sklearn's StackingClassifier does this via its cv argument.

Bagging vs boosting vs stacking?

Bagging: parallel training of the same model on bootstrap samples, averaged — reduces variance. Boosting: sequential models each fitting the ensemble's errors — reduces bias. Stacking: heterogeneous models combined by a learned meta-model — exploits complementary strengths.

What are SHAP values?

Feature attributions based on Shapley values from cooperative game theory: each feature's average marginal contribution to the prediction over all feature orderings. They're additive (sum to prediction minus baseline), consistent, give local and (aggregated) global explanations, and are computed exactly and fast for trees with TreeSHAP.

Permutation importance vs impurity importance vs SHAP?

Impurity (MDI): fast, training-data based, biased toward high-cardinality features. Permutation: model-agnostic, measured on validation data as the score drop after shuffling a feature; can be misleading with correlated features. SHAP: per-prediction additive attributions with solid theory; global importance = mean |SHAP|; more expensive for non-tree models.

What is a partial dependence plot and its limitation?

It shows the average model prediction as one (or two) features vary, marginalising over the others. Limitations: assumes features are independent (creates unrealistic combinations when correlated — ALE plots fix this) and averaging hides heterogeneous effects (ICE curves reveal them).

How do you know if more data will help?

Plot a learning curve: if the validation score is still rising and the train–validation gap is large at full size, more data should help (variance-limited). If both curves have plateaued close together, more data won't help — you need better features or a more expressive model.

What is error analysis and why does it matter?

Systematically examining where the model fails: slicing metrics by segments, inspecting misclassified examples, categorising error types and estimating how much each category costs. It focuses effort on the fixes with the highest payoff (e.g., 40% of errors are from one mislabeled source) instead of blind tuning.

LIME vs SHAP?

LIME fits a local interpretable surrogate (sparse linear model) on perturbed samples around a prediction — model-agnostic but unstable and dependent on kernel width/sampling. SHAP has game-theoretic guarantees (local accuracy, consistency) and consistent global aggregation; KernelSHAP is like LIME with a specific weighting that recovers Shapley values.

How would you explain a complex model to a non-technical stakeholder?

Lead with what it predicts and how well vs the current process (in business terms). Show the top drivers globally (SHAP summary in plain words), a couple of individual examples (“this customer is high risk mainly because of 3 missed payments and high utilisation”), the limitations/when not to trust it, and how it'll be monitored.

Model accuracy improved offline by 2% but the A/B test shows no lift. Why?

Offline metric not aligned with the business metric; leakage or optimistic offline evaluation; train/serve skew; distribution shift between offline data and live traffic; feedback loops; the improvement is in segments that don't affect the outcome; latency increase hurting UX; underpowered experiment or novelty effects.

When would you NOT use an ensemble?

Strict latency/memory budgets, need for simple explanations (regulated credit decisions), marginal gains not worth maintenance and debugging complexity, or when a single well-tuned model is already near the noise ceiling.
