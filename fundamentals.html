The end-to-end ML workflow

  1. Frame the problem: business objective → ML task, target definition, success metric, baseline, constraints (latency, interpretability).
  2. Data: collect, understand (EDA), check quality and leakage, define train/validation/test splits (by time/group if needed).
  3. Features: cleaning, encoding, scaling, engineering, selection.
  4. Modelling: baseline → simple model → stronger models; CV; tune hyperparameters.
  5. Evaluation: held-out test, error analysis, slices/fairness, calibration, business impact estimate.
  6. Deployment & monitoring: serving, drift/performance monitoring, retraining, A/B test (see MLOps).

The bias–variance trade-off

∑ Decomposition of expected squared error
$$\mathbb E\big[(y-\hat f(x))^2\big]=\underbrace{\big(\mathbb E[\hat f(x)]-f(x)\big)^2}_{\text{bias}^2}+\underbrace{\mathbb E\big[(\hat f(x)-\mathbb E[\hat f(x)])^2\big]}_{\text{variance}}+\underbrace{\sigma^2}_{\text{irreducible noise}}$$

Expectations are over training sets drawn from the same distribution. Bias: error from wrong assumptions (model too simple). Variance: sensitivity to the particular training sample (model too flexible). Noise can't be reduced by any model.

🧒 In plain English

Darts analogy: high bias = all darts clustered, but away from the bullseye (consistently wrong). High variance = darts scattered all over (inconsistent). You want them clustered on the bullseye.

Loss vs metric: the loss is what the optimiser minimises (must be differentiable/convenient); the metric is what the business cares about (F1, revenue, recall at k). They often differ — choose a loss that aligns with the metric and tune thresholds/hyperparameters on the metric.

Optimisation basics

  • Gradient descent: \(\theta\leftarrow\theta-\eta\nabla L\). Batch (all data, stable, slow), stochastic (one row, noisy, can escape shallow minima), mini-batch (standard).
  • Learning rate: too large → divergence/oscillation; too small → slow. Schedules (step decay, cosine), adaptive optimisers (Momentum, RMSProp, Adam).
  • Convexity: convex losses (linear/logistic regression, SVM) have one global minimum; neural nets are non-convex.
  • Feature scaling makes loss contours rounder → faster convergence.
  • Second-order methods (Newton, L-BFGS) use curvature: fewer iterations, more cost per iteration.
  • Coordinate descent (Lasso), closed form (OLS, Ridge), EM (mixtures), greedy (trees).

MLE vs MAP

Maximum likelihood: \(\hat\theta=\arg\max_\theta P(\text{data}\mid\theta)\). Maximum a posteriori: \(\hat\theta=\arg\max_\theta P(\text{data}\mid\theta)P(\theta)\) — MLE plus a prior, which acts as regularisation (Gaussian prior → L2, Laplace prior → L1). With lots of data the likelihood dominates and MAP → MLE. Full Bayesian inference keeps the whole posterior instead of a point estimate.

No free lunch, Occam's razor & the curse of dimensionality

  • No free lunch: averaged over all possible problems, no algorithm beats another — performance comes from assumptions matching the data. Hence: try several models, validate empirically.
  • Occam's razor: among models with similar validation performance, prefer the simpler one (generalises better, cheaper, more interpretable).
  • Curse of dimensionality: as d grows, data become sparse, distances concentrate, and the samples needed grow exponentially. Hurts kNN, clustering, density estimation most. Mitigate with feature selection, dimensionality reduction, regularisation, domain knowledge.

Interview questions

Explain the bias–variance trade-off.

Expected test error = bias² + variance + irreducible noise. Bias is error from overly simple assumptions (underfitting); variance is error from sensitivity to the specific training sample (overfitting). Increasing model complexity typically lowers bias and raises variance; the goal is the complexity that minimises total error, found via validation. Regularisation, more data and ensembling shift the trade-off.

How do you detect and prevent overfitting?

Detect: training performance much better than validation/CV performance; learning curves with a persistent gap. Prevent: more data or augmentation, simpler model, regularisation (L1/L2, dropout), early stopping, feature selection, ensembling (bagging), proper CV for tuning, and removing leakage.

What is the difference between supervised and unsupervised learning?

Supervised learning trains on labelled examples to predict a target (classification/regression) and is evaluated against true labels. Unsupervised learning has no labels and finds structure — clusters, low-dimensional representations, density/anomalies — and evaluation is harder (internal metrics, downstream usefulness).

Parametric vs non-parametric models?

Parametric models have a fixed number of parameters and strong functional assumptions (linear regression, logistic regression, Naive Bayes) — efficient, need less data, may underfit. Non-parametric models grow in complexity with data (kNN, trees, kernel methods, GPs) — flexible, need more data, risk overfitting, often slower at prediction.

Generative vs discriminative models?

Generative models learn P(x|y) and P(y) (hence the joint) and use Bayes' rule to classify; they can generate samples and handle missing data (Naive Bayes, GMM, HMM). Discriminative models learn P(y|x) or the boundary directly (logistic regression, SVM, trees). Discriminative models usually have lower asymptotic error; generative ones can be better with little data.

Why do we need a separate validation and test set?

The validation set (or CV) is used repeatedly for model selection and hyperparameter tuning, so performance on it is optimistically biased. The test set is touched once at the end to give an unbiased estimate of generalisation. Reusing the test set for decisions turns it into another validation set.

What is the curse of dimensionality?

As features grow, volume grows exponentially, so data become sparse, distances between points concentrate (nearest ≈ farthest), and the amount of data needed to generalise grows exponentially. Distance-based methods suffer most. Remedies: feature selection, dimensionality reduction, regularisation, domain knowledge.

What is the difference between a loss function and an evaluation metric?

The loss is optimised during training and needs mathematical convenience (differentiable, convex where possible) — e.g. log-loss. The metric measures what the business cares about and may be non-differentiable — e.g. F1, precision@k, revenue. Choose a loss aligned with the metric and select thresholds/hyperparameters on the metric.

Batch vs stochastic vs mini-batch gradient descent?

Batch uses the full dataset per update: accurate gradients, expensive, smooth convergence. Stochastic uses one sample: cheap and noisy, can escape shallow local minima, needs decaying learning rates. Mini-batch (32–1024) balances both and exploits vectorised hardware — the default in practice.

What is the relationship between MLE, MAP and regularisation?

MLE maximises the likelihood. MAP maximises likelihood × prior; taking logs adds −log prior to the loss. A zero-mean Gaussian prior adds an L2 penalty (Ridge/weight decay); a Laplace prior adds an L1 penalty (Lasso). So regularisation = encoding a prior belief that parameters are small.

What would you do if your model performs well on training data but poorly in production?

Check for data leakage in training features; train/serve skew (different preprocessing or feature computation online); distribution shift (data/concept drift) between training period and now; a validation scheme that didn't mirror production (random split vs time split, unseen groups); label definition differences; and bugs in the serving pipeline. Then fix the root cause and set up monitoring.

How do you approach a new ML problem?

Clarify the business goal and how predictions will be used; define target, metric and baseline; check data availability, quality and leakage; choose a validation scheme mirroring production; build a simple baseline; iterate on features and models with error analysis; evaluate on slices; consider deployment constraints and monitoring; communicate trade-offs.

What is the no free lunch theorem and what does it mean in practice?

Averaged over all possible data-generating distributions, every learning algorithm performs equally. A model is only better when its inductive bias matches the problem. Practically: no universally best model — try several reasonable ones and validate on your data.

Can a model have both high bias and high variance?

Yes — e.g. a model with the wrong functional form (bias) that's also fit on tiny noisy data with many parameters (variance), or a deep tree on badly chosen features. The decomposition terms aren't strictly opposed; good features can reduce both.

What is inductive bias?

The set of assumptions a learning algorithm uses to generalise beyond seen data: linearity (linear models), smoothness/locality (kNN, RBF), axis-aligned piecewise-constant structure (trees), translation equivariance (CNNs), feature independence (Naive Bayes). Choosing a model is choosing an inductive bias.
