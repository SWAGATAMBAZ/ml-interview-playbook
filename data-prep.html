Data prep & feature engineering

Missing values, outliers, scaling, encoding, feature creation and selection, imbalanced classes and — above all — data leakage. Interviewers use these to separate people who've shipped models from people who've only done tutorials.

EDA checklist

  • Shape, dtypes, memory; what is one row?
  • Target distribution / class balance; how the label was created and when
  • Missingness per column and its pattern
  • Duplicates, constant / near-constant columns, ID-like columns
  • Univariate distributions, skew, impossible values
  • Outliers (box plots, z-scores, domain limits)
  • Cardinality of categoricals, rare levels
  • Correlations, multicollinearity (VIF), target relationships
  • Time coverage, seasonality, drift between periods
  • Leakage suspects: features too predictive, created after the outcome

⚠️ Leakage alert

Compute imputation statistics on the training fold only (put the imputer in a Pipeline). Filling with the mean of the whole dataset leaks test information.

Outliers

  • Detect: z-score (|z| > 3, assumes ~normal), IQR rule (below Q1 − 1.5·IQR or above Q3 + 1.5·IQR), modified z-score (median/MAD), Isolation Forest/LOF for multivariate, domain rules.
  • Decide: error (fix/remove) vs genuine extreme (keep!) vs the actual target of interest (fraud).
  • Treat: cap/winsorise (e.g. 1st/99th percentile), log/Box-Cox transforms, robust scalers, robust losses (Huber/MAE), tree models (robust to feature outliers).

💬 Which models need scaling?

Need it: anything distance- or gradient-based or penalised — kNN, K-means, SVM, PCA, linear/logistic regression with regularisation or GD, neural networks. Don't: tree-based models (decision trees, RF, GBMs) and Naive Bayes.

Feature engineering ideas

  • Transformations: log, sqrt, Box-Cox for skew; ratios (debt/income); differences
  • Interactions: products, crosses (city × device)
  • Binning: age bands, quantile bins (helps linear models capture non-linearity)
  • Polynomial / splines for linear models
  • Dates: day of week, month, holiday flags, time since event, cyclical sin/cos encoding of hour/month
  • Aggregations: per-customer mean/count/std over windows (RFM), group statistics
  • Text: TF-IDF, n-grams, embeddings, length/counts
  • Geo: distances, clusters, lat/long rotations
  • Domain knowledge beats everything: “days since last login” for churn
  • Missing indicators and count of missing per row

⚠️ Selection must happen inside CV

Selecting features using the full dataset (e.g. top 20 by correlation with y) and then cross-validating gives wildly optimistic scores — the classic leakage in Hastie et al. Put selection steps in the Pipeline.

Imbalanced classes

  1. Use the right metric: precision, recall, F1/Fβ, PR-AUC, recall@precision, cost — not accuracy.
  2. Stratified splits and stratified CV.
  3. Class weights / cost-sensitive learning (class_weight="balanced", scale_pos_weight).
  4. Resampling (training folds only!): random undersampling of the majority, random oversampling, SMOTE (synthetic minority points interpolated between a minority point and its minority neighbours), ADASYN, SMOTE-Tomek/ENN cleaning.
  5. Threshold tuning on validation data — often the single most effective step.
  6. Anomaly-detection framing for extreme imbalance; collect more positive examples.
  7. Recalibrate probabilities after weighting/resampling if probabilities are used.

Data leakage

Information that wouldn't be available at prediction time sneaks into training, producing great offline scores and disappointing production results.

Interview questions

How do you handle missing values?

First understand why they're missing (MCAR/MAR/MNAR) and how much. Options: drop rows/columns if few/mostly missing; simple imputation (median/mode) plus a missing-indicator flag; model-based (KNN, iterative/MICE); time-series fill (forward-fill/interpolate); or models that handle NaN natively (gradient boosting). Fit imputers on training data only, and validate the choice with CV.

Explain MCAR, MAR and MNAR.

MCAR: missingness is unrelated to any data — deleting is unbiased. MAR: missingness depends on observed variables — imputation conditioning on them works. MNAR: missingness depends on the unobserved value itself (e.g. high incomes withheld) — any method is biased without modelling the mechanism; missing indicators help capture it.

When should you normalise vs standardise?

Standardise (z-score) as the general default for linear models, SVM, PCA, kNN, neural nets — it centres and handles unbounded data. Min-max normalise when you need a bounded range (e.g. pixel intensities, some NN inputs) and there are no strong outliers. RobustScaler with outliers. Trees need neither.

One-hot vs label encoding — when to use each?

One-hot for nominal categories in linear/distance-based models (no false order). Label/ordinal encoding for ordinal categories, or for tree models where arbitrary integer codes are acceptable. For high cardinality, use target/frequency/hashing encoding or native categorical support.

What is target encoding and its risk?

Replacing each category with the (smoothed) mean of the target for that category. Risk: target leakage — a row's own label influences its feature, and rare categories get extreme values that memorise labels. Mitigate with out-of-fold (cross-fitted) encoding, smoothing toward the global mean, and adding noise.

What is data leakage? Give examples.

When training uses information that won't be available at prediction time, inflating offline metrics. Examples: features recorded after the outcome (target leakage), fitting scalers/imputers/feature selection/target encoders on all data before splitting, random splits on time series, the same customer in train and test, duplicates across splits.

How do you deal with an imbalanced dataset?

Choose suitable metrics (PR-AUC, F1, recall@precision, cost); stratify splits; apply class weights or resampling (undersampling, SMOTE) only on training folds; tune the decision threshold on validation; consider ensemble methods like balanced random forests; get more minority data; recalibrate probabilities if needed.

How does SMOTE work and what are its drawbacks?

For each minority sample, pick one of its k nearest minority neighbours and create a synthetic point at a random position on the line between them. Drawbacks: can create noisy/overlapping samples in class-overlap regions, ignores the majority class distribution, struggles in high dimensions and with categorical features (use SMOTENC), and must be applied only inside training folds. Often class weights + threshold tuning do as well.

Filter vs wrapper vs embedded feature selection?

Filter: rank features by statistics independent of the model (correlation, chi², mutual information) — fast but ignores interactions. Wrapper: search subsets by training models (RFE, forward/backward) — accounts for interactions, expensive, overfit-prone. Embedded: selection during training (Lasso, tree importances) — efficient compromise.

How do you detect and treat outliers?

Detect with visualisation, z-scores, IQR rule, robust z (MAD), or multivariate methods (Isolation Forest, Mahalanobis). Investigate cause: data error (fix/remove), legitimate extreme (keep, maybe transform/cap), or the signal itself (fraud). Treatments: winsorising, log transforms, robust scaling, robust losses, tree models.

How would you encode a feature with 10,000 categories?

Target encoding with cross-fitting and smoothing, frequency encoding, hashing trick, grouping rare categories into “Other”, learned embeddings (neural nets), or native categorical support in LightGBM/CatBoost. Avoid one-hot (sparse and huge) unless using a linear model on sparse matrices.

Why should preprocessing be inside a pipeline?

So every transformation is fit only on training folds during CV and applied identically at inference — preventing leakage and train/serve skew — and so the whole thing can be tuned (GridSearch over preprocessing params) and serialised as one artifact.

How would you encode cyclical features like hour of day?

Map to the unit circle: sin(2π·hour/24) and cos(2π·hour/24), so 23:00 and 00:00 are close. Trees can also handle raw hour with splits, and one-hot works if each value has enough data.

Which algorithms are sensitive to feature scaling and which aren't?

Sensitive: kNN, K-means, SVM, PCA, LDA, regularised linear/logistic regression, anything trained by gradient descent (neural nets). Insensitive: decision trees, random forests, gradient boosting, Naive Bayes (per-feature distributions).
