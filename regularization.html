Ridge, Lasso & Elastic Net

Three ways to stop a linear model from over-trusting its training data: Ridge shrinks every weight, Lasso pushes useless weights to exactly zero, and Elastic Net blends the two. Interviewers love asking why Lasso zeroes features and Ridge doesn't.

🧒 In plain English

Plain linear regression is an eager student who'll use any clue to fit the training data perfectly, including coincidences. Regularisation adds a “complexity tax”: every bit of weight a feature gets costs a penalty, so the model only gives weight to features that truly earn it.

Ridge is like a flat tax: everyone's weight is shrunk, nobody is removed. Lasso is a tax with a fixed fee: small contributors find it's not worth paying and drop out completely (weight = 0), so you get automatic feature selection. Elastic Net charges a bit of both.

How it works, step by step (no maths)

  1. Scale the features first (standardise). The penalty treats all weights equally, so units must be comparable.
  2. Fit as usual (minimise the errors) plus a penalty on the size of the weights.
  3. Pick the strength of the penalty (alpha / λ). Zero gives plain OLS; very large shrinks everything to nothing.
  4. Choose alpha with cross-validation (RidgeCV, LassoCV, ElasticNetCV), i.e. the value with the best validation error.
  5. Read the result. Ridge gives all small-but-non-zero weights. Lasso gives a short list of surviving features.
🎯 Say this in the interview (30 seconds)

“Regularisation adds a penalty on coefficient size to the loss, trading a little bias for a big drop in variance. Ridge (L2) penalises squared weights. It shrinks all coefficients smoothly and handles multicollinearity by sharing weight among correlated features. Lasso (L1) penalises absolute weights, which drives some exactly to zero, so it does feature selection, but among correlated features it tends to pick one arbitrarily. Elastic Net mixes both, so you get sparsity plus stable, grouped selection. I standardise features, tune alpha (and l1_ratio) with cross-validation, and never penalise the intercept.”

Must-know points for interviews

  • Why regularise? To reduce overfitting (variance) when there are many features, correlated features, or more features than rows.
  • Ridge (L2): shrinks all weights toward zero but never exactly to zero. Great with multicollinearity. Always has a unique solution.
  • Lasso (L1): sets some weights exactly to zero, which is built-in feature selection. Unstable when features are correlated, since it picks one somewhat at random.
  • Elastic Net: L1 + L2. Correlated features are kept or dropped together. Best when p ≫ n or there are groups of correlated features.
  • Alpha (λ) controls strength. Bigger means simpler, more biased, less variance. Tune it with cross-validation.
  • Always standardise features, or the penalty unfairly hits features measured in small units.
  • The intercept isn't penalised.
  • In sklearn's LogisticRegression, C = 1/λ, so a smaller C means stronger regularisation. This is a classic gotcha.
  • The same idea appears everywhere: weight decay in neural nets, λ/α in XGBoost.

Going deeper: advanced intuition

why Lasso hits zero

The diamond has corners

Picture the allowed weights as a shape. For L2 it's a circle, for L1 a diamond. The best-fit solution touches the shape where the error contours first meet it, and a diamond's corners stick out and lie on the axes, where some weights equal zero. A circle has no corners, so Ridge rarely lands exactly on an axis.

the push

Constant vs proportional pressure

L1 pushes every weight toward zero with the same force, however small the weight, so tiny weights get pushed all the way to zero. L2's push weakens as the weight shrinks, so weights get small but never vanish.

correlated features

Sharing vs picking

Given two near-identical features, Ridge splits the weight between them (stable). Lasso gives it all to one and zeroes the other, and which one wins can flip with a small change in the data. Elastic Net keeps or drops them as a group.

Bayesian view

Penalties are beliefs

Ridge equals believing beforehand that weights are small and bell-shaped (Gaussian prior). Lasso equals believing most weights are exactly zero and a few are big (Laplace prior).

bias–variance

Why a biased model wins

Shrinking weights deliberately biases them, but it cuts the variance (how much they jump between samples) much more. The total test error goes down. That's the whole game.

inference caveat

No easy p-values

After Lasso picks features, the usual p-values are invalid because the selection used the same data. If you need inference, use a separate sample or post-selection methods.

When each one wins

Ridge (L2)

🏆 Pick Ridge when…
  • Most features are probably useful and many are correlated (e.g. marketing channels, sensor readings).
  • You want stable coefficients and predictions more than a short feature list.
  • There are more features than rows, and you want a smooth, unique solution.

Lasso (L1)

🏆 Pick Lasso when…
  • You suspect only a few features matter and want automatic feature selection for a simple, explainable model.
  • Serving cost depends on how many features you must compute or collect.

Elastic Net

🏆 Pick Elastic Net when…
  • There are many more features than rows (genomics, text) and groups of correlated features.
  • Lasso's selection keeps changing between runs, and you want sparsity that's stable.

⚠️ Common traps
  • Forgetting to standardise, or fitting the scaler on all the data instead of inside a Pipeline (leakage).
  • Treating Lasso's chosen features as “the true causes”. The selection is unstable when features are correlated.
  • Reading coefficients without remembering they're shrunk (biased toward 0).
💼 Practical example to quote

Predicting house prices from 300 engineered features on 1,500 homes: plain OLS overfits badly. LassoCV keeps about 40 features (easy to explain to the business), while RidgeCV gives slightly better RMSE. ElasticNetCV with l1_ratio around 0.5 lands close to Ridge's accuracy with around 60 features. Pick based on whether interpretability or accuracy matters more.

Practical tips & gotchas

  • Always standardise features first (inside a Pipeline so CV doesn't leak). The penalty treats every coefficient equally, so a feature measured in rupees vs crores would be penalised very differently.
  • Don't penalise the intercept; centre y or let sklearn handle it.
  • Use the one-standard-error rule: choose the largest α whose CV error is within 1 SE of the minimum — simpler model, similar accuracy.
  • Lasso feature selection is unstable with correlated features — use stability selection (repeat on bootstraps) or Elastic Net if you need reliable selection.
  • Lasso coefficients are biased toward 0; a common trick is “relaxed Lasso”: select with Lasso, refit OLS on the selected features.
  • Regularisation also applies to logistic regression, SVMs, neural nets (weight decay), and tree boosters (XGBoost's lambda/alpha on leaf weights).

The maths

∑ Objectives (scikit-learn conventions)
$$\textbf{Ridge:}\quad \min_\beta\ \lVert y-X\beta\rVert_2^2 + \alpha\lVert\beta\rVert_2^2 \quad\Rightarrow\quad \hat\beta = (X^TX+\alpha I)^{-1}X^Ty$$ $$\textbf{Lasso:}\quad \min_\beta\ \frac{1}{2n}\lVert y-X\beta\rVert_2^2 + \alpha\lVert\beta\rVert_1 \quad\text{(no closed form → coordinate descent)}$$ $$\textbf{Elastic Net:}\quad \min_\beta\ \frac{1}{2n}\lVert y-X\beta\rVert_2^2 + \alpha\rho\lVert\beta\rVert_1 + \frac{\alpha(1-\rho)}{2}\lVert\beta\rVert_2^2,\quad \rho=\texttt{l1\_ratio}$$
  • The intercept is not penalised.
  • Equivalent constrained form: minimise RSS subject to \(\sum\beta_j^2\le t\) (Ridge) or \(\sum|\beta_j|\le t\) (Lasso). Larger α ↔ smaller budget t.
  • Bayesian view: Ridge = MAP estimate with a Gaussian prior on β; Lasso = MAP with a Laplace prior (sharp peak at 0 → sparsity).
  • Ridge in SVD terms: shrinks each principal direction by \(d_j^2/(d_j^2+\alpha)\) — directions with small variance (the unstable ones) are shrunk the most.
  • Lasso coordinate update is soft-thresholding: \(\beta_j \leftarrow S(\rho_j,\alpha)=\operatorname{sign}(\rho_j)\max(|\rho_j|-\alpha,0)\), which sets small correlations exactly to 0.

Why Lasso gives exact zeros (three explanations)

geometry

Diamond vs circle

RSS contours are ellipses around the OLS solution. The L1 ball \(|\beta_1|+|\beta_2|\le t\) is a diamond with corners on the axes; the first contour to touch it usually hits a corner → a coefficient is 0. The L2 ball is round, so the tangent point is almost never on an axis.

gradient

Constant vs vanishing pull

The L2 penalty's gradient \(2\alpha\beta_j\) shrinks as β → 0, so it never quite reaches 0. The L1 penalty's (sub)gradient is a constant ±α regardless of size, so it can push a weak coefficient all the way to 0 and hold it there.

algorithm

Soft-thresholding

In coordinate descent, if a feature's correlation with the residual is below α, its coefficient is set to exactly 0. Ridge's update divides by \((1+\alpha)\) instead — proportional shrinkage, never zero.

Interview questions

What is the difference between L1 and L2 regularisation?

L1 (Lasso) penalises the sum of absolute coefficients, producing sparse models (exact zeros → feature selection), is non-differentiable at 0, and picks one of a group of correlated features. L2 (Ridge) penalises the sum of squares, shrinks all coefficients smoothly without zeroing, has a closed-form solution, and handles multicollinearity by spreading weight. Bayesian: L1 ↔ Laplace prior, L2 ↔ Gaussian prior.

Why does L1 produce sparse solutions but L2 doesn't?

Geometrically the L1 constraint region is a diamond (cross-polytope) whose corners lie on the axes; the elliptical RSS contours typically first touch it at a corner where some coordinates are 0. The L2 ball is smooth, so contact is generically off-axis. Analytically, the L1 subgradient is a constant ±α that can overpower a small data gradient and hold the coefficient at 0 (soft-thresholding), whereas the L2 gradient 2αβ vanishes near 0.

Why must you scale features before Ridge/Lasso?

The penalty is applied equally to all coefficients, but a coefficient's size depends on the feature's units. Unscaled, features with large ranges get small coefficients and are barely penalised, while small-range features are penalised heavily — the regularisation becomes arbitrary. Standardise inside a pipeline so the scaler is fit only on training folds.

How does Ridge help with multicollinearity?

With correlated features \(X^TX\) has tiny eigenvalues, so \((X^TX)^{-1}\) blows up the variance of β̂. Ridge adds α to every eigenvalue: \((X^TX+\alpha I)\) is always invertible and well-conditioned, which stabilises the coefficients (at the cost of some bias) and splits weight among correlated features.

When would you choose Elastic Net over Lasso?

When features are strongly correlated (Lasso arbitrarily keeps one and is unstable; Elastic Net's L2 part gives a grouping effect), and when p ≫ n (Lasso can select at most n features). It keeps Lasso's sparsity while gaining Ridge's stability.

How do you choose α?

Cross-validation over a log-spaced grid (RidgeCV, LassoCV, ElasticNetCV or GridSearchCV with the scaler inside a Pipeline). Pick the α with the lowest CV error or, for a simpler model, the largest α within one standard error of the minimum. Information criteria (AIC/BIC via LassoLarsIC) are faster alternatives.

What happens as α → 0 and α → ∞?

α → 0: the solution approaches OLS (high variance if overfitting). α → ∞: all coefficients go to 0 and the model predicts the mean (intercept only) — maximum bias. In between lies the bias–variance sweet spot.

Is the intercept regularised? Why not?

No. Penalising it would make predictions depend on the arbitrary origin of y (shifting y by a constant would change the fit). sklearn centres the data and fits the intercept separately.

Explain regularisation from a Bayesian perspective.

The posterior ∝ likelihood × prior. With Gaussian noise, the negative log-posterior is RSS/(2σ²) − log p(β). A Gaussian prior \(\beta_j\sim\mathcal N(0,\tau^2)\) gives the penalty \(\sum\beta_j^2/(2\tau^2)\) → Ridge with α = σ²/τ². A Laplace prior gives an L1 penalty → Lasso. So the MAP estimate equals the regularised solution; a tighter prior (small τ) = larger α.

Lasso selected different features on two bootstrap samples. Why, and what would you do?

Lasso is unstable under correlation: among correlated features it picks one nearly at random, and small data changes flip the choice. Remedies: Elastic Net, stability selection (fraction of bootstrap fits in which each feature is selected), group Lasso for known groups, or clustering correlated features first. And don't over-interpret Lasso's selection as causal importance.

Does regularisation reduce bias or variance?

It increases bias and reduces variance. It helps when the variance reduction outweighs the added bias — typically with many features, small n, noisy data or collinearity.

What is the relation between C in LogisticRegression and α?

C is the inverse of regularisation strength (C ≈ 1/α, scaled by n depending on the formulation). Large C = weak regularisation; small C = strong regularisation. Same idea in SVMs.

Why can't Lasso be solved with the normal equation or plain gradient descent?

|β| isn't differentiable at 0, so there's no closed form and the gradient is undefined at exactly the points we care about. We use coordinate descent with soft-thresholding (sklearn), LARS (which traces the whole path), proximal gradient (ISTA/FISTA), or subgradient methods (which don't produce exact zeros).

Name other forms of regularisation in ML.

Early stopping, dropout, weight decay, data augmentation, tree constraints (max_depth, min_samples_leaf, pruning), shrinkage/learning rate and subsampling in boosting, limiting the number of features (feature selection), ensembling, label smoothing, adding noise.
