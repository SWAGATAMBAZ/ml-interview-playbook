NumPy from scratch

Write strat_split(y, test_size, seed) that returns (train_idx, test_idx) such that each class contributes round(test_size × class_count) rows to the test set (shuffle within each class with np.random.default_rng(seed)). Indices must be disjoint and cover all rows.

Implement a class MyScaler with fit(X) (store mean and std per column; use std = 1 for constant columns), transform(X) and fit_transform(X). It must match sklearn.preprocessing.StandardScaler.

Write a generator kfold(n, k, seed) yielding (train_idx, val_idx) pairs: shuffle indices once, split into k folds whose sizes differ by at most 1 (first n % k folds get one extra, like sklearn).

Implement softmax(Z) row-wise (subtract the row max for stability) and cross_entropy(Z, y) = mean of −log softmax(Z)[i, y_i], computed via log-sum-exp so it doesn't overflow for huge logits.

Given a user × item rating matrix R (0 = not rated), write similar_items(R, item, k) returning the indices of the k items most cosine-similar to item (item vectors are columns), excluding the item itself, most similar first. Vectorise it.

Implement sgd_linreg(X, y, lr, epochs, batch, seed) for linear regression (with intercept as w[0]). Each epoch: shuffle rows, iterate over mini-batches, update with the batch MSE gradient. Return the weights.

Write roc_points(y, s) returning arrays (fpr, tpr) starting at (0, 0), using each distinct score as a threshold (predict positive if score ≥ threshold, thresholds in decreasing order). Then auc_trap(fpr, tpr) with the trapezoid rule.

For each user you have a ranked list of recommended item IDs and a set of relevant items. Implement precision_at_k, recall_at_k (per user) and mrr(all_recs, all_rel) (mean over users of 1/rank of the first relevant item, 0 if none).

pandas feature engineering

From tx (customer_id, date, amount), build a DataFrame rfm indexed by customer_id with columns recency (days between snapshot and last purchase), frequency (# transactions) and monetary (total amount), using only transactions before the snapshot date.

pd.get_dummies on train and test separately produces mismatched columns. Write encode(train, test, col) returning (train_enc, test_enc) with identical columns derived from the training categories only (unseen test categories → all zeros). Drop the original column.

scikit-learn craft

Create Winsorizer(BaseEstimator, TransformerMixin) with parameters lower=0.01, upper=0.99: fit learns per-column quantiles from training data; transform clips to them. Then use it inside a pipeline with LinearRegression as pipe and make sure GridSearchCV can tune winsorizer__upper.

A missed fraud (FN) costs ₹5,000, a false alarm (FP) costs ₹200. Write cost(y_true, y_pred) returning total cost, wrap it as cost_scorer = make_scorer(cost, greater_is_better=False), and use it in GridSearchCV over class_weight ∈ [None, {0: 1, 1: 5}, {0: 1, 1: 25}] for LogisticRegression → search.

Given test labels and model scores, compute a 95% percentile bootstrap CI for ROC-AUC with 1,000 resamples (resample rows with replacement; skip resamples containing a single class) → ci. Report it like you would to a stakeholder.

Capstone: end-to-end modelling under interview conditions

You get a messy loan dataset (numeric NaNs, categoricals, ~13% defaults). In ≤ 30 minutes: (1) split off a stratified 20% test set (random_state=0); (2) build a leak-free Pipeline with a ColumnTransformer and HistGradientBoostingClassifier; (3) tune 2–3 hyperparameters with RandomizedSearchCV (scoring "average_precision", ≤ 12 iterations, 3-fold) → search; (4) report test PR-AUC → test_ap and ROC-AUC → test_auc; (5) top-3 permutation-importance features on the test set → top3.

HistGradientBoosting handles NaN natively, so numeric imputation is optional; one-hot (or OrdinalEncoder + categorical_features) for the categoricals.
