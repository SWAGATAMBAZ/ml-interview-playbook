Naive Bayes

A probability-based classifier that “counts and multiplies”. It's absurdly fast, works with tiny data and remains a strong baseline for text such as spam filtering, sentiment and document tagging. Interviewers check whether you understand the “naive” assumption and smoothing.

🧒 In plain English

An email arrives containing “free”, “winner” and “click here”. Is it spam? Naive Bayes starts from how common spam is in general (say 30%), then, for each word, asks “how much more often does this word appear in spam than in normal mail?” and nudges the guess up or down. It multiplies all these nudges together and picks the class with the higher final score.

The “naive” part: it treats every word as independent evidence, even though “click” and “here” clearly come together. It's a wrong assumption, yet the model still ranks classes surprisingly well.

How it works, step by step (no maths)

  1. Count class frequencies (the prior), e.g. 30% spam, 70% not spam.
  2. For each class, count how often each feature value appears, e.g. “free” appears in 20% of spam but 1% of normal mail.
  3. Add a small count to everything (Laplace smoothing) so a word never seen in spam doesn't make the probability exactly zero.
  4. For a new email, combine the prior with every word's evidence. Adding logs avoids tiny numbers.
  5. Predict the class with the highest score. That's the whole model: training is one pass of counting.
🎯 Say this in the interview (30 seconds)

“Naive Bayes applies Bayes' theorem with the naive assumption that features are conditionally independent given the class. It predicts the class that maximises the prior times the product of per-feature likelihoods, computed as a sum of logs for numerical stability. Training is just counting, so it's extremely fast, needs little data and supports online updates. The variants are Gaussian for continuous features, Multinomial for word counts and Bernoulli for binary presence, with Laplace smoothing to avoid zero probabilities. Its class rankings are often good even though the independence assumption is violated, but its probabilities are poorly calibrated, usually too extreme.”

Must-know points for interviews

  • Naive assumption: features are independent given the class. It's almost always false, but the model still works because classification only needs the right winner, not exact probabilities.
  • Three variants: Gaussian (continuous features), Multinomial (word counts, TF-IDF), Bernoulli (word present or absent). Complement NB suits imbalanced text.
  • Laplace smoothing (alpha) stops a single unseen word from zeroing out a class.
  • Use logs so that multiplying thousands of small probabilities doesn't underflow to 0.
  • Very fast and data-efficient: one counting pass, works with hundreds of examples, and supports partial_fit for streaming.
  • Probabilities are badly calibrated (over-confident) because correlated evidence is double-counted. Use calibration if you need real probabilities.
  • Generative model: it learns how each class generates the data, unlike logistic regression, which learns the boundary directly.
  • It handles many features (100k-word vocabularies) with ease.

Going deeper: advanced intuition

why it still works

Right ranking, wrong confidence

Double-counting correlated words inflates the scores of both classes in similar ways, so the winner is often unchanged. That's why accuracy is good but probabilities near 0 or 1 can't be trusted.

generative vs discriminative

NB vs logistic regression

NB reaches its (higher) best error with very few examples. Logistic regression needs more data but ends up lower. Small data → NB, more data → logistic. It's a classic Ng & Jordan result.

it's linear

A linear model in disguise

Multinomial and Bernoulli NB produce a decision boundary that's linear in the feature counts, the same shape as logistic regression, only with weights set by counting instead of optimising.

smoothing

Alpha is regularisation

A bigger alpha pulls every word's probability toward uniform, which means less trust in rare words. Tune it with cross-validation like any other regulariser.

correlated features

Duplicates are dangerous

Add the same feature twice and NB counts its evidence twice. Remove near-duplicate features or use logistic regression.

Gaussian NB

Bell-curve assumption

For continuous features, each class is assumed to produce a bell curve per feature. Skewed features hurt, so transform them (log) or bin them.

When Naive Bayes wins (and when it doesn't)

🏆 Pick Naive Bayes when…
  • The task is text classification: spam, sentiment, support-ticket routing, news categories. These are high-dimensional sparse word counts.
  • Training data is tiny (hundreds of labelled examples).
  • You need real-time training or streaming updates, or training on huge data on one machine.
  • You need a baseline in five minutes before trying anything heavier.

💼 Practical example to quote

Routing customer-support emails into 12 queues with only 2,000 labelled tickets: Multinomial NB on TF-IDF trains in under a second, retrains every night as agents relabel tickets, and gets about 85% accuracy as a baseline. Upgrade to logistic regression or a fine-tuned transformer later, once more labels exist.

Bayes' theorem

∑ Posterior ∝ likelihood × prior
$$P(y\mid x)=\frac{P(x\mid y)\,P(y)}{P(x)}\ \propto\ P(x\mid y)\,P(y)$$
🧒 In plain English

An email contains “free”, “winner” and “click”. How likely is spam? Start from how common spam is (prior), then for each word multiply by how much more often it appears in spam than in normal mail (likelihood). The “naive” part: treat each word's evidence as if it were independent of the others.

Laplace (additive) smoothing

If the word “crypto” never appeared in a non-spam training email, \(P(\text{crypto}\mid\text{ham})=0\), and one occurrence would zero out the whole product — no matter how strong the other evidence. Add α (α = 1 Laplace, α < 1 Lidstone) to every count:

∑ Smoothed estimate
$$P(x_j\mid y=k)=\frac{\text{count}(x_j,k)+\alpha}{\text{count}(k)+\alpha\cdot V}$$

V = number of possible values (vocabulary size). GaussianNB uses var_smoothing instead: adds a fraction of the largest feature variance to all variances for numerical stability.

Worked example

Prior: P(spam) = 0.4. Likelihoods: P(“free”|spam) = 0.3, P(“free”|ham) = 0.02; P(“meeting”|spam) = 0.01, P(“meeting”|ham) = 0.1. Email contains both words:

spam score ∝ 0.4 × 0.3 × 0.01 = 0.0012; ham score ∝ 0.6 × 0.02 × 0.1 = 0.0012 → a tie, so P(spam | email) = 0.5. Remove “meeting” and spam wins 0.12 vs 0.012 → P(spam) ≈ 0.91.

Pros, cons & when to use

✅ Strengths

  • Very fast to train & predict; scales to huge vocabularies
  • Works with little training data; few parameters
  • Handles many features & multiclass naturally; online learning
  • Strong baseline for text: spam, sentiment, topic, intent

❌ Weaknesses

  • Independence assumption rarely true → can't model interactions
  • Poorly calibrated, overconfident probabilities (correlated features double-count evidence)
  • GaussianNB assumes normal features
  • Usually beaten by logistic regression / boosting with enough data

The Naive Bayes model

∑ Decision rule (in log space)
$$\hat y=\arg\max_k\ \Big[\log P(y=k)+\sum_{j=1}^d\log P(x_j\mid y=k)\Big]$$

Logs turn a product of many small numbers (underflow risk) into a sum. P(x) is the same for every class, so it's dropped for classification.

  • Training = counting/averaging: class frequencies, and per-class feature distributions. O(n·d) single pass, trivially parallel and supports online updates (partial_fit).
  • Multinomial and Bernoulli NB are linear classifiers in log space (log-odds is linear in feature counts).

Interview questions

Why is Naive Bayes called “naive”?

Because it assumes all features are conditionally independent given the class, so P(x₁,…,x_d | y) = ∏ P(x_j | y). This is rarely true (words like “New” and “York” co-occur), but it makes the model tractable with little data.

Why does Naive Bayes work well even though the independence assumption is violated?

Classification only needs the correct class to have the highest score, not accurate probabilities. Dependencies often affect all classes similarly or cancel out, so the argmax is still right even if the probabilities are badly miscalibrated (Domingos & Pazzani). Its low variance also helps on small/high-dimensional data.

What is Laplace smoothing and why is it needed?

Adding a pseudo-count α (1 for Laplace) to each feature-class count so no conditional probability is zero. Without it, a single unseen word in a test document makes the whole class likelihood zero regardless of all other evidence.

Difference between Multinomial, Bernoulli and Gaussian NB?

Multinomial models counts/frequencies (how many times each word appears). Bernoulli models binary presence/absence and explicitly penalises absent features — good for short texts. Gaussian models continuous features with a per-class normal distribution.

Is Naive Bayes generative or discriminative? What does that mean?

Generative: it models the joint distribution via P(x|y)P(y) and could in principle generate data. Discriminative models (logistic regression, SVM) model P(y|x) or the boundary directly. Generative models need less data and handle missing features naturally; discriminative ones usually win with lots of data.

Why do we use log probabilities?

Multiplying hundreds of probabilities < 1 underflows to 0 in floating point. Log turns products into sums, is monotonic (argmax unchanged), and is numerically stable; normalise with log-sum-exp when you need actual probabilities.

Are Naive Bayes probabilities reliable?

Not usually — correlated features are counted as independent evidence, pushing probabilities toward 0 or 1. Use NB for ranking/classification; if you need probabilities, calibrate (CalibratedClassifierCV with isotonic or sigmoid).

How does Naive Bayes handle continuous and missing features?

Continuous: GaussianNB, or discretise into bins and use categorical/multinomial NB, or kernel density estimates. Missing: simply drop that feature's term from the sum for that sample (a generative advantage) — though sklearn requires imputation.

Show that Multinomial NB is a linear classifier.

log P(y=1|x) − log P(y=0|x) = log(π₁/π₀) + Σ_j x_j·log(θ_{j1}/θ_{j0}). This is b + wᵀx with w_j = log(θ_{j1}/θ_{j0}), linear in the counts x — the same functional form as logistic regression but with weights estimated generatively rather than by maximising conditional likelihood.

When would you use Naive Bayes over logistic regression?

Very small training sets, extremely high-dimensional sparse text, need for millisecond training/online updates, or as a quick baseline. With ample data and correlated features, logistic regression or boosting typically perform better.

Compute P(spam | “free”) given P(spam)=0.2, P(free|spam)=0.5, P(free|ham)=0.05.

Numerator 0.2 × 0.5 = 0.10; evidence = 0.10 + 0.8 × 0.05 = 0.14; posterior = 0.10 / 0.14 ≈ 0.714.
