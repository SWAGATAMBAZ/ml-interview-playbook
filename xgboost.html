XGBoost, LightGBM & CatBoost

The three production gradient-boosting libraries. Interviews ask what makes each one fast and accurate: XGBoost's second-order objective and regularised gain, LightGBM's histograms, leaf-wise growth, GOSS and EFB, CatBoost's ordered boosting and target statistics for categoricals — and, very practically, which hyperparameters you tune and how.

🎯 Say this in the interview

“All three are gradient-boosted decision trees. XGBoost adds a regularised objective — penalties on the number of leaves (γ) and leaf weights (λ, α) — and uses a second-order Taylor expansion, so each leaf's optimal weight is \(-G/(H+\lambda)\) and split gain has a closed form; plus sparsity-aware splits for missing values, histogram methods, column subsampling and parallelism. LightGBM is built for speed: histogram binning, leaf-wise (best-first) growth, GOSS to subsample low-gradient rows and EFB to bundle sparse features, with native categorical support. CatBoost uses symmetric (oblivious) trees and ordered boosting with ordered target statistics, which handles categorical features without target leakage and works well with defaults. I tune learning rate with early stopping, then tree complexity (max_depth / num_leaves, min_child_weight), sampling, and regularisation.”

XGBoost: the maths you're expected to know

∑ Regularised objective at round t
$$\mathcal L^{(t)}=\sum_i l\big(y_i,\hat y_i^{(t-1)}+f_t(x_i)\big)+\Omega(f_t),\qquad \Omega(f)=\gamma T+\tfrac12\lambda\sum_{j=1}^T w_j^2+\alpha\sum_j|w_j|$$

Second-order Taylor expansion with \(g_i=\partial_{\hat y}l\), \(h_i=\partial^2_{\hat y}l\):

$$\mathcal L^{(t)}\approx\sum_i\Big[g_if_t(x_i)+\tfrac12h_if_t(x_i)^2\Big]+\Omega(f_t)$$

Grouping by leaf j with \(G_j=\sum_{i\in I_j}g_i,\ H_j=\sum_{i\in I_j}h_i\) (taking α = 0):

$$w_j^*=-\frac{G_j}{H_j+\lambda}\qquad \text{score}=-\frac12\sum_j\frac{G_j^2}{H_j+\lambda}+\gamma T$$ $$\text{Gain}=\frac12\Big[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\Big]-\gamma$$
  • A split is only kept if Gain > 0, i.e. it must beat γ → built-in pruning (trees grow to max_depth, then prune back negative-gain splits).
  • For squared error, g = ŷ − y and h = 1, so \(H_j\) is just the leaf's row count; min_child_weight is the minimum sum of hessians in a leaf (for log-loss \(h=p(1-p)\), so it also blocks leaves of very confident points).
  • Using the Hessian (Newton boosting) gives better step sizes and lets any twice-differentiable loss plug in.

XGBoost engineering features

  • Sparsity-aware split finding: learns a default direction for missing values at each split.
  • Split finding: exact greedy, approximate (weighted quantile sketch), and tree_method="hist" (default in 2.x) with binned features.
  • Column block structure + cache-aware access, parallel split search across features, out-of-core, GPU (device="cuda").
  • Shrinkage (eta), row subsampling, column subsampling by tree/level/node.
  • Monotonic and interaction constraints, custom objectives, native categorical support (enable_categorical=True with pandas category dtype).

LightGBM: what makes it fast

histograms

Binned features

Continuous values bucketed into ≤ max_bin (255) bins; split search is O(bins) instead of O(n). Histogram subtraction: a child's histogram = parent − sibling.

growth

Leaf-wise (best-first)

Always split the leaf with the largest loss reduction (vs XGBoost's default level-wise). Lower loss for the same number of leaves, but can overfit small data — control with num_leaves, min_data_in_leaf, max_depth.

GOSS

Gradient-based One-Side Sampling

Keep all rows with large gradients (poorly fit), randomly sample those with small gradients and upweight them to keep the distribution unbiased.

EFB

Exclusive Feature Bundling

Merge mutually exclusive sparse features (rarely non-zero together, e.g. one-hot columns) into a single feature → fewer features to scan.

categoricals

Native categorical splits

Sorts categories by gradient statistics to find good many-vs-many partitions, no one-hot needed.

⚠️ num_leaves vs max_depth

A depth-d level-wise tree has up to 2^d leaves. In LightGBM keep num_leaves < 2^max_depth (e.g. depth 7 → num_leaves ≤ 127, often 31–63) or leaf-wise growth will build very deep, overfit trees.

CatBoost: categorical-first boosting

  • Ordered target statistics: encodes a category for row i using the target mean of preceding rows in a random permutation (plus a prior), so a row's own label never leaks into its encoding.
  • Ordered boosting: residuals for a row are computed by a model that didn't see that row, fighting the prediction shift / target leakage of standard boosting.
  • Oblivious (symmetric) trees: the same split condition across a whole level → very fast inference, strong regularisation, less overfitting.
  • Automatic categorical feature combinations; strong defaults (less tuning); good with text features; GPU support.

Tuning playbook & practical tips

  1. Start: learning_rate 0.05–0.1, n_estimators large (e.g. 5000) with early stopping (50–100 rounds) on a validation fold.
  2. Tune complexity: max_depth 3–10 / num_leaves 15–255, min_child_weight 1–20 / min_child_samples 5–100.
  3. Tune sampling: subsample & colsample 0.5–1.0.
  4. Tune regularisation: reg_lambda 0–20, reg_alpha 0–5, gamma 0–5.
  5. Lower learning rate (0.01–0.02), re-run early stopping, refit.
  6. Use Optuna/random search over these; evaluate with the business-relevant metric (eval_metric="auc", "aucpr", "logloss", "rmse"…).
  • Imbalance: scale_pos_weight ≈ #neg/#pos (ranking/AUC improves; probabilities become miscalibrated — recalibrate if needed).
  • Monotone constraints enforce business logic (risk must increase with debt-to-income) — great for regulated models.
  • Explainability: use SHAP (TreeSHAP) rather than gain importance; XGBoost's "weight" (split count), "gain" and "cover" importances disagree.
  • Don't one-hot high-cardinality features for LightGBM/CatBoost — use native categorical handling.

Interview questions

What makes XGBoost different from classic gradient boosting?

A regularised objective (γ per leaf, L2/L1 on leaf weights), second-order (Newton) optimisation with gradients and hessians giving closed-form leaf weights and gains, sparsity-aware handling of missing values, weighted quantile sketch / histogram split finding, column subsampling, built-in pruning via γ, and systems work: parallel, cache-aware, out-of-core and GPU training.

Derive the optimal leaf weight in XGBoost.

For leaf j, the second-order objective is G_j w + ½(H_j + λ) w² (+ γ). Differentiating and setting to zero: G_j + (H_j + λ) w = 0 ⇒ w* = −G_j / (H_j + λ). Plugging back gives the leaf score −½ G_j²/(H_j + λ), from which the split gain formula follows.

What do gamma, lambda and min_child_weight do in XGBoost?

gamma (min_split_loss): minimum gain required to make a split — prunes weak splits. lambda (reg_lambda): L2 penalty on leaf weights, shrinking them toward 0 and appearing in the denominator H + λ. min_child_weight: minimum sum of hessians in a child; blocks tiny or ultra-confident leaves. All three make trees more conservative.

Level-wise vs leaf-wise tree growth?

Level-wise (XGBoost default) splits all nodes at a depth before going deeper — balanced trees, more robust. Leaf-wise (LightGBM) always splits the leaf with the highest gain — reaches lower loss with fewer leaves, faster, but can produce deep unbalanced trees that overfit small data; constrain with num_leaves, min_data_in_leaf and max_depth.

What are GOSS and EFB in LightGBM?

GOSS (Gradient-based One-Side Sampling) keeps all high-gradient (under-fit) rows and a random sample of low-gradient rows, reweighting the sampled ones to keep gain estimates unbiased. EFB (Exclusive Feature Bundling) merges sparse features that are rarely non-zero simultaneously into one, reducing the number of features scanned. Both cut training cost with little accuracy loss.

How does CatBoost handle categorical features?

With ordered target statistics: under a random permutation, each row's category is encoded with the (prior-smoothed) mean target of rows that come before it, so its own label doesn't leak. It also builds combinations of categorical features greedily. Ordered boosting applies the same idea to residual computation to avoid prediction shift.

How does XGBoost handle missing values?

During training each split tries sending all missing values left and then right and keeps the direction with higher gain — a learned default direction per node. At inference, missing values follow that direction. No imputation needed (though missingness that's informative is captured automatically).

Which hyperparameters would you tune first for XGBoost/LightGBM?

Learning rate + number of trees (via early stopping), then tree complexity (max_depth / num_leaves, min_child_weight / min_child_samples), then sampling (subsample, colsample_bytree), then regularisation (lambda, alpha, gamma). Finish by lowering the learning rate and re-fitting with early stopping.

How do you handle class imbalance in XGBoost?

scale_pos_weight ≈ negatives/positives (or sample weights), an imbalance-aware eval metric (aucpr) for early stopping, threshold tuning on validation data, and possibly max_delta_step for extreme imbalance with log-loss. Recalibrate probabilities if you reweighted.

Why does XGBoost use the second derivative?

A second-order approximation gives a Newton step: leaf values account for curvature (−G/H) rather than using a fixed line search, converging faster and more accurately, and it provides a unified closed-form gain for any twice-differentiable loss, making custom objectives easy (just supply g and h).

Which feature importance would you trust from XGBoost?

Built-in types disagree: weight (# splits) favours continuous features, gain (average loss reduction) is better but still biased, cover is sample-count based. For reliable global and local explanations use SHAP (TreeSHAP), or permutation importance on held-out data.

When would you pick CatBoost over LightGBM?

Many (high-cardinality) categorical features, small-to-medium datasets where overfitting is a risk, limited tuning time (strong defaults), or when fast and stable inference matters (symmetric trees). LightGBM for very large datasets and fastest training.

What are monotonic constraints and why use them?

They force the model's prediction to be non-decreasing (or non-increasing) in a chosen feature, e.g. credit risk must not decrease as utilisation rises. They encode domain knowledge, improve generalisation/robustness, and satisfy regulators. Set via monotone_constraints in XGBoost/LightGBM.

Why do gradient-boosted trees usually beat deep learning on tabular data?

Tabular features are heterogeneous, often irregular with sharp thresholds and uninformative columns; trees handle mixed scales, missing values and categorical splits natively, are robust to irrelevant features, and need less data and tuning. Neural nets have smooth inductive biases better suited to images, text and audio.
