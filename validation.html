Cross-validation & hyperparameter tuning

How you estimate performance and choose hyperparameters decides whether your offline numbers mean anything. Know every CV scheme and when to use it, nested CV, and the tuning methods from grid search to Bayesian optimisation and successive halving.

Train / validation / test

  • Train: fit parameters. Validation (or CV): select models and hyperparameters. Test: touched once, for the final unbiased estimate.
  • Typical splits: 60/20/20 or 80/20 with CV on the 80%. With millions of rows, 98/1/1 is fine.
  • The split must mirror production: random for i.i.d. data, by time for temporal data, by group when entities repeat, stratified for imbalance.

💬 Choosing K

Larger K → each training set closer to full size (less pessimistic bias) but more compute and more correlated folds (estimate variance can rise). K = 5 or 10 is the standard compromise. Report mean ± std across folds.

Nested cross-validation

If you tune hyperparameters with CV and report the best CV score, that score is optimistically biased — you picked the max of noisy estimates. Nested CV: an inner CV loop tunes hyperparameters inside each outer training fold; the outer loop scores the whole tuning procedure on untouched folds. Use it to report an unbiased estimate (esp. small data or comparing algorithms); the final model is then tuned with ordinary CV on all data.

Parameters vs hyperparameters

Parameters are learned from data during training (regression coefficients, tree splits, neural weights). Hyperparameters are set before training and control the learning process or model capacity (learning rate, max_depth, C, k, regularisation α, number of trees). Hyperparameters are tuned on validation data, never on the test set.

Search spaces: sample scale-type parameters (learning rate, C, α, γ) log-uniformly; integer ranges for depth/leaves; conditional spaces (kernel → gamma) in Optuna.

Validation curves & learning curves

  • Validation curve: train & validation score vs one hyperparameter → shows under/overfitting regions and the optimum.
  • Learning curve: score vs training-set size → tells you whether more data will help (gap closing) or you need a more expressive model (both plateau low).

Best practices & traps

  • Put all preprocessing (scaling, imputation, encoding, selection, resampling) in a Pipeline so CV refits it per fold. For SMOTE use imblearn.pipeline.Pipeline.
  • Use the same CV splits (fixed random_state) when comparing models; consider paired tests on fold scores.
  • Tune on the metric you'll be judged on (scoring="average_precision", custom scorers).
  • Don't over-tune to the validation set; prefer simpler models within 1 SE (one-standard-error rule).
  • Final model: refit on all training data with the chosen hyperparameters (refit=True), then evaluate once on test.
  • Check fold-score variance — big variance means unstable models or heterogeneous data.

Interview questions

What is cross-validation and why use it?

A resampling method that splits data into K folds, trains on K−1 and validates on the remaining one, rotating so every fold is validated once. It gives a lower-variance, more data-efficient estimate of generalisation than a single split, plus a spread (std) of performance, and is used for model selection and tuning.

What CV would you use for time-series data, and why?

Time-ordered splits — expanding or sliding window (TimeSeriesSplit / rolling-origin backtests), optionally with a gap to prevent leakage via lag features and a horizon matching production. Random K-Fold would train on the future and validate on the past.

When should you use GroupKFold?

When multiple rows belong to the same entity (patient, user, device, store) and the model will be applied to new entities. Otherwise rows from the same entity appear in both train and validation, and the model gets credit for memorising entity-specific patterns.

What is nested cross-validation?

Two loops: inner CV selects hyperparameters on each outer training fold; the outer CV evaluates the tuned model on held-out outer folds. It gives an unbiased estimate of the performance of the whole model-building procedure, avoiding the optimism of reporting the best inner CV score.

Grid search vs random search?

Grid search evaluates every combination of predefined values — exhaustive but exponential in the number of hyperparameters and wasteful when only a few matter. Random search samples configurations from distributions; for the same budget it explores more distinct values of each important hyperparameter and usually finds equal or better results.

How does Bayesian optimisation work for hyperparameter tuning?

It builds a probabilistic surrogate model of the objective (Gaussian process or TPE) from past trials and uses an acquisition function (expected improvement, UCB) to pick the next configuration balancing exploration and exploitation. It needs fewer evaluations than random search for expensive models; tools: Optuna, Hyperopt, scikit-optimize.

Why is stratified K-Fold important for classification?

It keeps class proportions consistent across folds, reducing variance of the estimate and preventing folds with very few (or zero) minority examples, which would make metrics like recall or AUC unstable or undefined.

What is the bias–variance trade-off in choosing K for K-Fold?

Small K trains on less data, so estimates are pessimistically biased; large K (LOOCV) trains on nearly all data (low bias) but the training sets overlap heavily, so fold scores are highly correlated and the estimate can have high variance, plus more compute. K = 5–10 balances these.

How do you avoid data leakage during cross-validation?

Fit every data-dependent step (imputation, scaling, encoding, feature selection, resampling, target encoding) inside the CV loop via pipelines; respect group and time structure in splits; deduplicate before splitting; never look at test data while developing.

What is successive halving / Hyperband?

Multi-fidelity tuning: evaluate many configurations with a small budget (few samples, epochs or trees), keep the top 1/η, multiply the budget by η, and repeat. Hyperband runs several such brackets with different trade-offs between number of configs and starting budget. sklearn: HalvingGridSearchCV / HalvingRandomSearchCV.

Difference between a validation curve and a learning curve?

Validation curve: training and validation scores vs a hyperparameter value — find the complexity sweet spot. Learning curve: scores vs training-set size — diagnose whether more data (high variance) or more capacity (high bias) will help.

After cross-validation, which model do you deploy?

Usually refit the chosen pipeline with the selected hyperparameters on all available training data (more data → better model); the CV score estimates its performance. Alternatives: an ensemble of the K fold models (common in competitions), or for time series, the model trained on the most recent window.
