CatBoost

Yandex's “Categorical Boosting”. It's gradient boosting designed for data full of text categories (city, product, brand), with a clever no-peeking trick that prevents target leakage, plus symmetric trees that are hard to overfit and very fast to predict with. Its defaults are famously strong.

🧒 In plain English

Models need numbers, but much real data is words: “Mumbai”, “iPhone”, “Gold plan”. A popular shortcut is to replace each category with its average outcome, e.g. Mumbai → 7% churn. The danger is that each row's own answer gets baked into its number. That's like a student whose cheat-sheet was written using the answer key: perfect in practice, useless in the real exam (this is target leakage).

CatBoost's fix is to shuffle the rows and encode each one using only the rows that came before it, the way a teacher might grade each paper against only the papers already handed in. No row ever sees its own answer. It also uses symmetric trees, where every node at the same depth asks the same question, so the trees are simple, steady and lightning-fast at prediction time.

How it works, step by step (no maths)

  1. Shuffle the rows (it actually uses several random orders).
  2. Turn categories into numbers without peeking. For each row, the category's value is the average target of earlier rows with the same category, blended with the overall average so rare categories aren't extreme. These are called ordered target statistics.
  3. Build combinations automatically, e.g. city × device, when they help.
  4. Compute errors without peeking either (ordered boosting). Each row's error is judged by a model that hasn't trained on that row.
  5. Grow a symmetric (oblivious) tree. It picks one question per depth level and applies it to every node at that level.
  6. Add the tree × learning rate, repeat, and early-stop. The defaults (depth 6, an auto-chosen learning rate) usually work well.

Must-know points for interviews

  • Just pass the raw categorical columns with cat_features=[...]. No one-hot encoding or manual target encoding needed.
  • Target leakage is the problem with naive target encoding: a category seen once is encoded as its own label. Ordered target statistics fix it.
  • Ordered boosting fixes prediction shift: in normal boosting, residuals are computed by a model that already saw that row, so they're over-optimistic.
  • Oblivious trees: each level has the same split, so a depth-6 tree has exactly 64 leaves. That gives strong regularisation and very fast, branch-free prediction.
  • Great defaults. It's often competitive with zero tuning: depth 6, l2_leaf_reg 3, and an automatically chosen learning rate.
  • Low-cardinality categories are one-hot encoded automatically (one_hot_max_size). Higher-cardinality ones get target statistics.
  • Training is slower than LightGBM on big numeric data on CPU. The GPU version is fast. Inference is very fast.
  • It also handles text and embedding features, missing numeric values, ranking objectives and multi-class problems.

Going deeper: advanced intuition

leakage

Why naive target encoding fails

Imagine customer_id as a feature. Each ID appears once, so its “average churn” is exactly that customer's own label. The model learns “encoding = answer”, scores 100% in training and collapses on new data. Ordered statistics never let a row see its own label.

prior

Smoothing rare categories

A city seen twice shouldn't be encoded as 0% or 100%. Blending with the global average (the prior) pulls rare categories toward the middle until there's enough evidence.

permutations

Why several shuffles

Rows near the start of a shuffle have little history, so their encodings are noisy. Using several permutations averages that noise out.

oblivious trees

A tree that is really a lookup table

With the same question at every level, a depth-6 tree is just 6 yes/no answers forming a 6-bit index into 64 leaf values. Prediction becomes a few comparisons and one array lookup, which is ideal for low-latency serving.

regularisation

Symmetry as a brake

Forcing the same split across a level stops the tree from carving out tiny special-case regions. It's a strong built-in defence against overfitting, especially on small datasets.

serving

Training vs inference encodings

At prediction time the encodings use statistics from the full training set. The ordering trick only matters during training, to keep the learning honest.

When CatBoost wins (and when it doesn't)

🏆 Pick CatBoost when…
  • There are many categorical columns, especially high-cardinality ones: retail (store, SKU, brand), insurance (car make/model, region), travel (route, hotel), HR (role, department, location).
  • The dataset is small to medium and overfitting is a real risk.
  • You have little time to tune and want a strong result from defaults, e.g. a quick baseline, a hackathon or a first production version.

Interview questions

What problem does CatBoost solve that other boosters don't?

Categorical features without manual encoding and without target leakage. Its ordered target statistics encode each row's category using only earlier rows' labels, and ordered boosting computes residuals with models that haven't seen the row.

What is target leakage in target encoding, and how does CatBoost avoid it?

Naive target encoding replaces a category by its mean target computed on all rows, including the row itself, so the feature contains the answer (extreme for rare categories). The model looks great in training and fails on new data. CatBoost uses a random permutation and only rows before the current one, plus a prior for smoothing, so a row never sees its own label. K-fold target encoding is the manual alternative.

What are oblivious (symmetric) trees and why use them?

Trees where every node at a given depth uses the same split. A depth-d tree is d binary tests mapping to 2^d leaves — effectively a lookup table. They're strongly regularised (less overfitting), stable, and extremely fast to evaluate, which suits low-latency serving.

What is prediction shift and how does ordered boosting fix it?

In standard boosting, the residual for a row is computed by a model that was trained on that same row, so residuals on training data are systematically smaller than on new data — the gradient estimates are biased. Ordered boosting keeps models trained on prefixes of a permutation and computes each row's residual with a model that never saw it.

How does CatBoost handle categorical features?

With ordered target statistics: under a random permutation, each row's category is encoded with the (prior-smoothed) mean target of rows that come before it, so its own label doesn't leak. It also builds combinations of categorical features greedily. Ordered boosting applies the same idea to residual computation to avoid prediction shift.

When would you pick CatBoost over LightGBM?

Many (high-cardinality) categorical features, small-to-medium datasets where overfitting is a risk, limited tuning time (strong defaults), or when fast and stable inference matters (symmetric trees). LightGBM for very large datasets and fastest training.
