Support Vector Machines (SVM)

A classifier that draws the boundary with the widest possible safety gap between classes, and with the “kernel trick” it can bend that boundary into curves. It was the king of ML before boosting and deep learning, and is still asked about for its elegant ideas: margin, support vectors, C, gamma and kernels.

🧒 In plain English

Imagine red and blue marbles on a table, and you need to lay a ruler between them. Many positions work, but the safest one leaves the widest empty “street” on both sides, because new marbles are then less likely to land on the wrong side. SVM finds exactly that street.

Only the marbles touching the edge of the street matter. They're the support vectors, and moving any other marble changes nothing. And if no straight ruler can separate them (blue in a ring around red)? The kernel trick imagines lifting the marbles into a higher dimension, say pushing the centre ones upward, where a flat sheet can separate them. Seen back on the table, that sheet is a circle.

How it works, step by step (no maths)

  1. Scale the features. SVM is distance-based, so units matter.
  2. Look for the boundary with the widest margin between the classes.
  3. Allow some mistakes (soft margin). Real data overlaps, so points may sit inside the street or on the wrong side, at a cost controlled by C.
  4. Need a curved boundary? Choose a kernel (RBF is the usual default), which measures similarity as if in a richer feature space.
  5. The final model depends only on the support vectors, the critical points near the boundary.
  6. Tune C and gamma together with cross-validation.
🎯 Say this in the interview (30 seconds)

“An SVM finds the hyperplane that maximises the margin between classes, and only the points on or inside the margin, the support vectors, define it. The soft-margin version uses hinge loss and a parameter C to trade margin width against training errors: large C means fewer violations and a risk of overfitting, small C means a wider, more regularised margin. The kernel trick replaces dot products with a kernel function such as RBF, giving non-linear boundaries without ever computing the high-dimensional features. For RBF, gamma controls how far each point's influence reaches. I scale features, tune C and gamma jointly, and use a linear SVM for large sparse text data. Kernel SVMs scale poorly beyond roughly 100k rows.”

Must-know points for interviews

  • Maximum margin means better generalisation: a wide gap is robust to small changes in new data.
  • Support vectors are the only points that matter. The model is sparse and memory-light at prediction time.
  • C (soft margin): large C means strict, a narrow margin and overfitting risk. Small C means tolerant, a wide margin and more bias. It works like 1/regularisation strength.
  • Kernels: linear (text, many features), polynomial (interactions), RBF (default for curved boundaries).
  • gamma (RBF): large gamma means each point's influence is very local, giving wiggly boundaries that overfit. Small gamma means smooth boundaries that can underfit.
  • Hinge loss: correct points comfortably outside the margin cost zero, so the model ignores easy points.
  • Scaling is mandatory.
  • No native probabilities. probability=True adds a slow calibration step (Platt scaling).
  • Training time grows roughly quadratically to cubically with the number of rows for kernel SVMs, so they're impractical beyond about 100k rows. LinearSVC scales well.
  • SVR is the regression version: it fits a tube of width ε and ignores errors inside it.

Going deeper: advanced intuition

kernel trick

Similarity instead of features

The SVM only ever needs to know “how similar are these two points?”. A kernel computes the similarity you'd get in a huge (even infinite) feature space, without building that space. RBF says “points are similar if they're close”.

C × gamma

The two dials together

High C with high gamma memorises every point (islands around each one). Low C with low gamma is almost a straight line. The sweet spot lies on a diagonal of the grid, so always search them jointly, on a log scale.

hinge vs log-loss

SVM vs logistic regression

Both draw a linear boundary. Logistic regression listens a little to every point. SVM listens only to points near the boundary, which makes it more robust to far-away points but stops it from giving natural probabilities.

high dimensions

Why SVMs love text

When there are more features than rows, classes are often linearly separable, and maximising the margin is a strong regulariser there. That's why linear SVMs were state of the art for text classification.

sparsity

Few support vectors = simple model

If only 5% of the points are support vectors, the boundary is simple and likely to generalise. If almost all points are support vectors, the classes overlap heavily or C and gamma are off.

duality

Why kernels are possible

The optimisation can be rewritten so the data appears only through pairwise similarities (the “dual”). That rewrite is what lets you swap in any valid kernel.

When SVM wins (and when it doesn't)

🏆 Pick SVM when…
  • The data is small to medium (hundreds to tens of thousands of rows) with a complex but clean boundary (RBF kernel).
  • There are more features than rows, as in genomics, text and some bioinformatics. Use a linear SVM.
  • The task is text classification with TF-IDF (LinearSVC is fast and very strong).
  • You want a model robust to points far from the boundary, and probabilities aren't needed.

💼 Practical example to quote

Cancer subtype classification from gene expression: 200 patients × 20,000 genes. More features than rows rules out most models. A linear SVM (or one with a modest RBF kernel), with C tuned by cross-validation, gives a strong, well-regularised boundary where tree ensembles overfit.

💬 Tuning together

C and γ interact — tune them jointly on a 2-D log grid (the classic heat-map). Diagonal bands of similar performance are common: larger γ needs smaller C to stay regularised.

Support Vector Regression

SVR fits a function and ignores errors smaller than ε (the ε-insensitive tube); points outside the tube become support vectors and pay a linear penalty weighted by C. It's robust to small noise and outliers, works with kernels, but needs scaled X (and often scaled y).

Practical notes

  • Scale features — margins and RBF distances are scale-dependent.
  • Complexity: kernel SVC training ≈ O(n²) to O(n³), memory for the kernel matrix → slow beyond ~50–100k rows. For big data use LinearSVC / SGDClassifier(loss="hinge"), or kernel approximation (Nystroem, RBFSampler) + a linear model.
  • No native probabilities: decision_function gives signed distances; use Platt scaling.
  • Multiclass: SVC uses one-vs-one (K(K−1)/2 classifiers); LinearSVC uses one-vs-rest.
  • Robust in high dimensions (d ≫ n), e.g. text, genomics, because complexity depends on the margin, not d.

Pros, cons & when to use

✅ Strengths

  • Effective in high-dimensional spaces, even d > n
  • Max-margin → good generalisation; convex (unique global optimum)
  • Flexible non-linear boundaries via kernels
  • Memory-efficient prediction (support vectors only)

❌ Weaknesses

  • Doesn't scale to very large n (kernel)
  • Sensitive to C, γ, kernel choice and feature scaling
  • No direct probabilities; hard to interpret with kernels
  • Noisy, overlapping classes → many support vectors, slow

Maths

Hard margin (separable data)

∑ Primal
$$\min_{w,b}\ \frac12\lVert w\rVert^2\quad\text{s.t.}\quad y_i(w^Tx_i+b)\ge1\ \ \forall i,\qquad y_i\in\{-1,+1\}$$

Distance from a point to the hyperplane is \(|w^Tx+b|/\lVert w\rVert\); with the canonical scaling (closest points have \(|w^Tx+b|=1\)) the margin width is \(2/\lVert w\rVert\), so maximising it = minimising \(\lVert w\rVert^2\).

Soft margin

∑ Primal with slack ξ
$$\min_{w,b,\xi}\ \frac12\lVert w\rVert^2 + C\sum_i\xi_i\quad\text{s.t.}\quad y_i(w^Tx_i+b)\ge1-\xi_i,\ \xi_i\ge0$$ $$\Longleftrightarrow\ \min_{w,b}\ \frac12\lVert w\rVert^2 + C\sum_i\max\big(0,\,1-y_i(w^Tx_i+b)\big)\quad\text{(hinge loss)}$$

Dual (where kernels come from)

∑ Dual problem
$$\max_\alpha\ \sum_i\alpha_i-\frac12\sum_{i,j}\alpha_i\alpha_jy_iy_j\,x_i^Tx_j\quad\text{s.t.}\ 0\le\alpha_i\le C,\ \sum_i\alpha_iy_i=0$$ $$f(x)=\operatorname{sign}\Big(\sum_{i\in SV}\alpha_iy_i\,K(x_i,x)+b\Big)$$

KKT conditions: \(\alpha_i=0\) for points outside the margin (irrelevant), \(0<\alpha_i<C\) on the margin, \(\alpha_i=C\) inside/misclassified. The non-zero α's are the support vectors.

The kernel trick

The dual only needs dot products \(x_i^Tx_j\). Replace them with \(K(x_i,x_j)=\phi(x_i)^T\phi(x_j)\) for some feature map φ — possibly infinite-dimensional — without ever computing φ. A valid kernel must be symmetric positive semi-definite (Mercer's condition).

KernelK(x, z)Notes
Linear\(x^Tz\)High-dimensional sparse data (text); use LinearSVC for speed
Polynomial\((\gamma x^Tz+r)^d\)Feature interactions up to degree d
RBF / Gaussian\(\exp(-\gamma\lVert x-z\rVert^2)\)Default; infinite-dimensional φ; similarity decays with distance
Sigmoid\(\tanh(\gamma x^Tz+r)\)Rarely used; not always PSD

Example: for 2-D \(x\), \((x^Tz)^2=\phi(x)^T\phi(z)\) with \(\phi(x)=(x_1^2,\sqrt2x_1x_2,x_2^2)\) — a circle in 2-D becomes a plane in 3-D.

Interview questions

What are support vectors?

Training points that lie on the margin boundary or violate it (inside the margin or misclassified) — those with non-zero dual coefficients α. They alone define the hyperplane; removing any other point leaves the solution unchanged.

What is the role of C in SVM?

C is the penalty on slack (margin violations), i.e. inverse regularisation. Large C → fewer violations, narrower margin, risk of overfitting outliers. Small C → wider margin, more violations tolerated, smoother boundary, more bias.

What does gamma do in an RBF kernel?

γ controls how far a single training point's influence reaches: K = exp(−γ‖x − z‖²). Large γ → narrow bumps, very wiggly boundary, overfitting; small γ → broad influence, smooth almost-linear boundary, underfitting. Tune jointly with C.

Explain the kernel trick.

Algorithms that depend on data only through dot products (like the SVM dual) can replace xᵢᵀxⱼ with a kernel K(xᵢ, xⱼ) = φ(xᵢ)ᵀφ(xⱼ). This implicitly operates in a high (even infinite) dimensional feature space where data may be linearly separable, without ever computing φ — cost depends on n, not on the dimension of φ.

Why maximise the margin?

A larger margin means the classifier is robust to small perturbations and, from statistical learning theory, has lower capacity (VC-dimension bound depends on margin, not dimension), giving better generalisation guarantees. It also yields a unique solution among all separating hyperplanes.

Hinge loss vs log loss — compare SVM and logistic regression.

Hinge loss is zero for points correctly classified beyond the margin, so only support vectors matter → sparse solution, no probabilities. Log loss is never zero, every point contributes, and it yields calibrated probabilities. Both are convex surrogates for 0-1 loss and use L2 regularisation; performance is often similar for linear problems.

Why is feature scaling important for SVM?

The margin is measured in Euclidean distance and the RBF kernel depends on ‖x − z‖, so large-scale features dominate both. Unscaled data also slows down solvers. Standardise inside a pipeline.

How does SVM handle multiclass classification?

Via decomposition: one-vs-one (K(K−1)/2 pairwise classifiers, majority vote — sklearn SVC) or one-vs-rest (K classifiers — LinearSVC). Crammer–Singer is a joint multiclass formulation.

Why solve the dual instead of the primal?

The dual depends on data only via dot products, enabling kernels; its size depends on n (not on the feature dimension); and the solution is sparse in α (support vectors). For linear SVMs with huge n and moderate d, the primal (LinearSVC, SGD) is actually faster.

When would you not use an SVM?

Very large datasets (kernel SVM scales ~n²–n³), lots of noise/overlap (many support vectors), when calibrated probabilities or interpretability are needed, or with heterogeneous tabular data where gradient boosting typically wins.

What makes a function a valid kernel?

Mercer's condition: K must be symmetric and positive semi-definite — every Gram matrix it produces has non-negative eigenvalues — so it corresponds to an inner product in some feature space. Sums, products and positive scalings of valid kernels are valid kernels.

How do you get probabilities from an SVM?

Platt scaling: fit a logistic regression on the SVM decision values using cross-validation (SVC(probability=True) or CalibratedClassifierCV). Isotonic regression is an alternative with more data.
