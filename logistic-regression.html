Logistic regression

Despite the name, it's a classification model: it predicts the probability of yes/no outcomes like churn, fraud or click. It's the default baseline for binary problems and the model regulators like most, because every coefficient has a clear meaning.

🧒 In plain English

Logistic regression first adds up evidence like linear regression does: “+2 points for a month-to-month contract, +1.5 for many complaints, −3 for a long tenure”. The total score can be any number, but a probability must sit between 0 and 1. So it passes the score through an S-shaped curve (the sigmoid): a very negative score gives about 0%, zero gives 50%, and a very positive score gives about 100%.

Finally you choose a cut-off: above 50% (or whatever threshold suits the business) means “will churn”.

How it works, step by step (no maths)

  1. Score each row: intercept plus a weight × each feature, exactly like linear regression.
  2. Squash the score into a probability with the S-curve.
  3. Judge the fit with log-loss. Being confidently wrong (saying 99% when the answer is no) is punished very heavily, and being unsure is punished mildly.
  4. Adjust the weights by gradient descent to minimise the log-loss. There's no closed-form answer, but the loss is bowl-shaped, so there's one best solution.
  5. Pick a decision threshold using precision/recall and business costs, not automatically 0.5.
🎯 Say this in the interview (30 seconds)

“Logistic regression models the log-odds of the positive class as a linear function of the features, and the sigmoid turns that into a probability. It's trained by maximum likelihood, which is the same as minimising log-loss (cross-entropy). That loss is convex, so gradient-based solvers find the global optimum. Each coefficient is the change in log-odds per unit of the feature, and exponentiating it gives an odds ratio. The decision boundary is linear, so non-linearity needs feature engineering. I use L2 or L1 regularisation, choose the threshold from precision–recall trade-offs, and handle imbalance with class weights.”

Must-know points for interviews

  • It's classification, called “regression” because it regresses the log-odds.
  • Odds ratio: exp(coefficient). Example: coefficient 0.7 → exp(0.7) ≈ 2, so each unit doubles the odds (not the probability).
  • Linear decision boundary. To capture curves, add interactions, polynomials or bins, or use trees.
  • Log-loss, not squared error. Squared error with a sigmoid isn't convex and gives weak gradients.
  • Outputs are well-calibrated probabilities by default. That's a big plus for risk scoring and expected-value decisions.
  • Threshold ≠ 0.5 by default. Tune it for the business cost of false positives vs false negatives.
  • Imbalanced data: use class_weight="balanced" or resampling, and evaluate with PR-AUC, recall and F1, not accuracy.
  • Regularised by default in sklearn (L2, C=1). Smaller C = stronger penalty. Scale the features.
  • Perfect separation makes coefficients run off to infinity, and regularisation fixes it.
  • Multiclass: one-vs-rest or softmax (multinomial).

Going deeper: advanced intuition

why log-odds

Evidence adds up

Log-odds turns “multiplying odds” into “adding points”, so independent clues simply add. That's why the model is a scorecard, and why banks have used logistic scorecards for decades.

the loss

Confident and wrong = disaster

Log-loss grows without limit as you approach 100% confidence in the wrong answer. That forces the model to stay humble, which is why its probabilities are usually trustworthy.

vs Naive Bayes

Discriminative vs generative

Logistic regression learns the boundary directly. Naive Bayes models how each class generates the data. With little data, NB often wins. With more data, logistic usually wins because it doesn't assume features are independent.

it's a neuron

Logistic = one-neuron network

A single neuron with a sigmoid activation and cross-entropy loss is logistic regression. Neural networks stack many of them.

interpretation trap

Odds are not probabilities

Doubling the odds moves a probability from 1% to about 2%, but from 50% to about 67%. The effect on probability depends on where you start.

calibration

Rebalancing breaks it

Class weights or oversampling shift the predicted probabilities upward. If you need true probabilities afterwards, recalibrate on untouched validation data.

When logistic regression wins (and when it doesn't)

🏆 Pick logistic regression when…
  • You need interpretable, auditable decisions: credit scorecards, medical risk, insurance (regulated industries).
  • You need well-calibrated probabilities to feed expected-value or pricing decisions.
  • The data is high-dimensional and sparse, like text with TF-IDF or one-hot IDs. Linear models are fast and strong there.
  • You want a fast baseline or need very low-latency scoring (a dot product).
  • The data is small to medium and the signal is roughly additive.

💼 Practical example to quote

Loan approval scorecard: a regulator requires the bank to explain every rejection. Logistic regression on binned features (WoE encoding) gives points per attribute, and odds ratios explain the decision. Its calibrated probability of default feeds directly into interest-rate pricing. Gradient boosting might add 1–2% AUC, but the explainability requirement wins.

Interpreting coefficients

  • \(w_j\) = change in log-odds per one-unit increase in \(x_j\), others fixed.
  • \(e^{w_j}\) = odds ratio: e.g. \(w=0.7\) → odds multiply by 2.01 (≈ doubles). \(w=-0.7\) → odds halve.
  • The effect on the probability is not constant — it depends on where you are on the sigmoid (largest near p = 0.5).
  • Intercept b: log-odds when all features are 0 (or at their means if centred).
  • Odds vs probability: p = 0.8 → odds = 4 (“4 to 1”).

⚠️ Not assumptions

Logistic regression does not assume normally distributed errors, homoscedasticity, or a linear relationship between x and y itself (only with the logit).

Multiclass

  • One-vs-Rest (OvR): K binary classifiers, pick the highest score. Probabilities don't naturally sum to 1 (sklearn normalises).
  • Multinomial / softmax: \(P(y=k\mid x)=\frac{e^{w_k^Tx}}{\sum_j e^{w_j^Tx}}\), trained with categorical cross-entropy. Default in sklearn's LogisticRegression for multiclass (lbfgs).
  • Ordinal logistic for ordered classes (ratings), not in sklearn (statsmodels OrderedModel).

Improving performance

  1. Scale features; encode categoricals (one-hot, drop one if unregularised).
  2. Capture non-linearity: splines / polynomial features, binning, interaction terms, log transforms of skewed inputs (it's still linear in the logit).
  3. Tune C and penalty with stratified CV; optimise the metric that matters (ROC-AUC, PR-AUC, log-loss).
  4. Imbalanced data: class_weight="balanced" or resampling, then tune the decision threshold; evaluate with PR-AUC / recall at fixed precision.
  5. Check calibration (reliability curve); usually decent out of the box, but class weighting / resampling distorts probabilities.
  6. Remove leakage-prone and redundant features; check VIF.

Pros, cons & when to use

✅ Strengths

  • Fast, scalable, few hyperparameters
  • Probabilities, generally well calibrated
  • Interpretable (odds ratios), regulatory-friendly (credit scoring)
  • Strong baseline; works well with high-dimensional sparse data (text, TF-IDF)

❌ Weaknesses

  • Linear decision boundary unless you engineer features
  • Struggles with complex interactions
  • Sensitive to outliers, multicollinearity, perfect separation
  • Needs scaling & encoding

The maths

∑ Model
$$z = w^Tx+b,\qquad \hat p=\sigma(z)=\frac{1}{1+e^{-z}},\qquad \log\frac{\hat p}{1-\hat p}=w^Tx+b$$

Loss: negative log-likelihood = binary cross-entropy

∑ Log-loss and its gradient
$$L(w)=-\frac1n\sum_{i=1}^n\Big[y_i\log\hat p_i+(1-y_i)\log(1-\hat p_i)\Big]$$ $$\nabla_w L=\frac1n X^T(\hat p-y)\qquad(\text{same form as linear regression!})$$

Uses \(\sigma'(z)=\sigma(z)(1-\sigma(z))\). The Hessian \(X^TSX\) with \(S=\operatorname{diag}(\hat p_i(1-\hat p_i))\) is positive semi-definite → convex. Solvers: lbfgs (default), newton-cg / IRLS (Newton's method), liblinear (coordinate descent), sag/saga (stochastic average gradient, large data, supports L1).

Why not mean squared error?

  • MSE composed with a sigmoid is non-convex in w → local minima.
  • Gradient of MSE contains \(\sigma'(z)\), which vanishes when the model is confidently wrong → learning stalls. Log-loss's gradient is simply \((\hat p-y)\), large when wrong.
  • Log-loss is the correct likelihood for Bernoulli outcomes, and it heavily penalises confident mistakes.

Perfect separation

If classes are perfectly separable, the MLE doesn't exist: pushing ‖w‖ → ∞ keeps decreasing the loss. Unregularised solvers diverge / warn. Regularisation (the default L2) fixes this.

Interview questions

Why is it called “regression” if it's used for classification?

It regresses the log-odds of the positive class on the features (a generalised linear model with a logit link). It outputs a continuous probability; classification comes from thresholding that probability.

Why do we use the sigmoid function?

It maps any real number to (0, 1), is monotonic and differentiable with a convenient derivative σ(1−σ), and is the inverse of the logit, so it follows naturally from modelling log-odds linearly (also the canonical link for the Bernoulli distribution).

Why not use MSE as the loss for logistic regression?

MSE through a sigmoid is non-convex (local minima) and its gradient is multiplied by σ'(z), which is tiny when the prediction is confidently wrong, so learning stalls. Log-loss is the negative Bernoulli log-likelihood, convex in w, and its gradient (p̂ − y)x is large exactly when the model is wrong.

How do you interpret a logistic regression coefficient?

A one-unit increase in x_j changes the log-odds by w_j, i.e., multiplies the odds by e^{w_j} (odds ratio), holding other features constant. E.g., w = 0.4 → odds × 1.49 (+49%). The change in probability depends on the baseline probability.

Is the decision boundary of logistic regression linear?

Yes: p̂ = 0.5 ⇔ wᵀx + b = 0, a hyperplane in feature space (any threshold t gives wᵀx + b = logit(t), still a hyperplane). It becomes non-linear in the original space only if you add non-linear features (polynomials, splines, interactions).

What are the assumptions of logistic regression?

Binary/categorical outcome; independent observations; linearity between continuous features and the log-odds; little multicollinearity; no extreme influential outliers; sufficiently large sample (≈10+ events per predictor). It does not assume normality, homoscedasticity or linear x–y relationships.

Does logistic regression have a closed-form solution?

No — setting the gradient Xᵀ(σ(Xw) − y) = 0 gives non-linear equations. It is solved iteratively: Newton–Raphson / IRLS, L-BFGS, coordinate descent (liblinear), or SGD/SAGA. Convexity guarantees a global optimum (if it exists).

What happens with perfectly separable data?

The likelihood keeps increasing as ‖w‖ → ∞ (probabilities pushed to exactly 0/1), so the MLE doesn't exist; coefficients and SEs blow up and solvers fail to converge. Fix: regularisation (default L2 in sklearn), Firth's penalised likelihood, or removing the perfectly predictive (often leaking!) feature.

How do you handle class imbalance with logistic regression?

class_weight="balanced" (or custom weights), resampling (undersample majority, SMOTE oversampling inside CV), and — most importantly — moving the decision threshold based on business costs or F-score on a validation set. Evaluate with PR-AUC, recall/precision, not accuracy. Note weighting/resampling biases predicted probabilities; recalibrate if you need true probabilities.

One-vs-rest vs multinomial (softmax) logistic regression?

OvR trains K independent binary models; simple and parallel, but probabilities aren't jointly modelled. Multinomial fits one model with a softmax over K linear scores and cross-entropy loss — coherent probabilities summing to 1, usually better calibrated; it's sklearn's default with lbfgs.

Logistic regression vs linear SVM?

Both are linear classifiers with L2 regularisation. LR minimises log-loss (every point contributes, gives probabilities); SVM minimises hinge loss (only margin violators / support vectors matter, no probabilities without Platt scaling, maximises the margin). SVM can be more robust to points far from the boundary; LR is better when you need calibrated probabilities.

Logistic regression vs Naive Bayes?

LR is discriminative (models P(y|x) directly); NB is generative (models P(x|y)P(y) with a feature-independence assumption). With little data NB converges faster and can win; with more data LR typically achieves lower asymptotic error (Ng & Jordan). In fact Gaussian NB with shared variances implies a linear (logistic-form) decision boundary.

What is the log-loss of a model that always predicts 0.5? What's a good log-loss?

ln 2 ≈ 0.693 for any labels. A useful baseline is predicting the base rate π: loss = −[π ln π + (1−π) ln(1−π)] (e.g., 0.199 for π = 5%). A model is only useful if it beats that baseline.

What is the gradient of the log-loss and how does it compare with linear regression?

∇L = (1/n) Xᵀ(σ(Xw) − y). It has the same structure as linear regression's Xᵀ(Xw − y) — residual times input — because both are GLMs using their canonical link. The Hessian is XᵀSX with S = diag(p(1−p)), used by Newton/IRLS.

Are logistic regression probabilities calibrated?

Generally yes when the model is well specified and unweighted, because maximising log-likelihood is a proper scoring rule. Strong regularisation, class weights, resampling or misspecification can miscalibrate it; check with a reliability diagram / Brier score and fix with Platt or isotonic calibration.

How would you capture non-linear effects in logistic regression?

Add polynomial or spline basis functions (SplineTransformer), bin continuous variables (WoE binning in credit scoring), log/ratio transforms, interaction terms, or kernel approximations (Nystroem + LR). If many interactions matter, move to tree ensembles.

Which metric would you use to evaluate a logistic regression model?

Depends on the goal: ROC-AUC for ranking quality, PR-AUC/F1/recall@precision for rare positives, log-loss/Brier for probability quality, calibration plots when probabilities drive decisions, and a business cost metric at the chosen threshold. Accuracy only with balanced classes and symmetric costs.
